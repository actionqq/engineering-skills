# v0.2 Frontend Method Family

v0.2 treats frontend prototype, frontend implementation, and frontend review as three delivery profiles over one design-method family.

## Shared method

The common method covers:

- product-vs-brand register;
- information hierarchy, layout, spacing, typography, color, and design-system continuity;
- anti-template / anti-slop heuristics;
- flows, forms, overlays, feedback, and complete UI states;
- keyboard/focus, baseline accessibility, responsive behavior, and content quality.

The method was synthesized after comparing Anthropic frontend-design, pbakaus/impeccable, nextlevelbuilder/ui-ux-pro-max-skill, tasteskill/tasteskill, Vercel web-interface-guidelines, and the existing Matt Pocock-derived prototype material.

## Delivery profiles

### frontend-prototype

Explores unresolved frontend experience with runnable artifacts. Settled business rules and technical design are inputs. Backend behavior may be stubbed when it is not the subject of the prototype. Completion is evidence about interaction and visual direction, not production readiness.

### implement

Uses the same design principles only when the requested change has a frontend surface. Its responsibility is production integration: real project architecture, real data boundaries, maintainable components, tests, performance and compatibility appropriate to the product. It must not restart open-ended visual exploration when an accepted design or prototype already exists.

### tech-review

Uses a frontend review lens only when the target contains user-facing UI. It checks implementation against the governing design, project conventions, interaction states, accessibility/responsive basics, and visible product quality. It remains evidence-oriented and read-only by default.

## Removed v0.1 overlap

The old generic prototype entry also covered business state modeling and engineering experiments. In v0.2:

- business behavior and state semantics stay with tech-design;
- technical spikes are methods invoked by design, implementation, research, or diagnosis when needed;
- the user-facing prototype entry is explicitly frontend-focused.

This keeps user entrypoints task-oriented while preventing implement and tech-review from becoming encyclopedic frontend Skills.
