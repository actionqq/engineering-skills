# Retrieval and Restoration

Use when deciding archive visibility, finding historical material, or restoring it to active use.

## Keep historical material findable without treating it as current

Active navigation should lead to maintained guidance and ongoing work, with a concise pointer to history. Archive navigation should identify topic, period/scope, reason, and successor where one exists. Large archives can have grouped indexes; a small archive does not need a second catalog system.

For current-behavior questions, start with current sources. For historical rationale, previous experiments, or explicit archive searches, include the relevant archive and label its date, scope, and lifecycle. Follow an active document's historical evidence link when needed; archival does not invalidate that evidence by itself. Before recreating an old investigation, check archive summaries for a relevant prior result.

Use index metadata or short summaries to discover likely matches, then read the actual relevant records. Do not claim to have searched all history after only scanning an index. Report current and historical matches distinctly when they disagree. A later file or a restored file does not automatically overrule the project's accepted authority.

Directory names alone do not control agent search, ingestion, or maintenance. Use existing project search/index conventions when they support active-versus-historical selection. Do not silently edit global agent instructions, tools, or ignore rules to enforce a filter. In a plain repository, clear entrypoints and historical banners establish a reading convention; report it as such, not as guaranteed exclusion from every search.

Archive maintenance normally repairs paths, indexes, metadata, or recoverability. Do not update every old dependency statement or rewrite historic test results to current conditions. If new evidence corrects a historical claim, retain the original account and append a dated correction or successor pointer. Avoid creating recurring freshness chores for deliberately historical records.

## Restore placement and reassess applicability

Reading or citing historical evidence does not require restoration. Restore when the user wants material active again or requests reversal of an archive operation. Locate the exact archived item and its operation record; resolve ambiguous matches before moving anything.

Before mutation, use [Execution and recovery](operations.md) for baseline preservation, collision checks, reference updates, and interruption handling. Determine what has changed since archival: current owners, replacements, scope, branch/release, requirements, paths, and recorded verification. Read the relevant successor rather than assuming the old location is still the right home.

If the original active path is occupied, do not overwrite it. Choose another authorized location, keep the item historical for reference, or resolve whether the user wants a new revision of the maintained document. An archived source and a current replacement can coexist without either being silently merged.

Restore only the intended item and its required attachments; retain any still-valid historical snapshots. Update active/archive indexes and references so readers can follow the transition. Record the restoration date, reason, and path mapping in the existing operation record. Preserve earlier archive events rather than erasing history.

Separate physical restoration from authority:

- Reopening a cancelled plan needs a real new work decision; moving the file back does not complete that decision.
- A superseded ADR remains superseded until an authorized decision changes the governing arrangement.
- A restored specification may need reconciliation with the current system before use.
- Historical passing tests remain historical; identify what needs revalidation without fabricating new results or invalidating unrelated evidence.

Verify content, placement, links, and navigation, then state whether the item is active and applicable, restored but pending reconciliation, or left historical because of a conflict. Repeated restoration should detect the existing result rather than duplicate files or indexes. If only retrieval was requested, return the relevant evidence and limits without changing lifecycle state.
