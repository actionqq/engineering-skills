# Independent Review and Synthesis

Use when the task requires independence or when distinct complex obligations justify separate review contexts. Separate headings inside one conversation do not create independence.

## Prepare a neutral review packet

Provide the requested objective, exact snapshot or content identity, governing requirements and standards, raw artifacts, relevant environment limits, and expected output form. Exclude the author's reasoning, suspected answer, prior proposed findings, and desired verdict unless reviewing those claims is explicitly the assignment.

Verify the actual context behavior of the available mechanism. A child that inherits the complete author conversation has not been isolated. Use a fresh supported context when authorized and available; otherwise perform ordinary review and disclose the independence limit. Do not create tools or session names that the current harness does not support.

## Select review dimensions deliberately

Separate project standards from task requirements when each warrants focused evidence gathering. Retain correctness and regression analysis: code can follow both documented sets and still contain a defect. Other focused dimensions may be useful for a specific risk, but do not impose a fixed agent count on every review.

Reviewers should use the same snapshot and form initial judgments before seeing each other's conclusions. Give each a clear responsibility that avoids duplicate full scans. Default permissions remain read-only.

## Synthesize findings, not votes

Validate each proposed finding against current evidence. Agreement does not prove correctness, and a minority finding can be the important one. Remove duplicates, preserve supporting locations and sources, and investigate conflicting interpretations instead of averaging verdicts.

Rank the combined result by consequence. Preserve the distinction between specification omissions, required-standard deviations, correctness defects, and optional suggestions without burying the most important defect under rigid report columns.

If code or design changes after review, identify affected findings and recheck the relevant scope. A complete re-review still requires the current whole; the previous reviewers' conclusions are historical material.

Report who or what actually performed each check, the snapshot, validation performed, and limits. Use “author self-check,” “single-context review,” or “independent review” according to the actual process, not the desired level of confidence.
